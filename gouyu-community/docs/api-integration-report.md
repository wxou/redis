## 3. 联调中修复的问题

1. `MemberProfile` 的 Java 字段误写为 `followRelationee`，MyBatis-Plus 因此查询不存在的 `follow_relationee` 列。字段已改为与包装后数据库一致的 `followee`。
2. 动态点赞使用原始 SQL 片段时写成 Java 字段名 `likeCount`，MySQL 无法识别。已改为实际列名 `like_count`。
3. 登出接口原为未实现占位。现在会删除当前 `authorization` 对应的 Redis 会话；验证旧令牌再次访问 `/member/me` 返回 HTTP 401。
4. 限时权益 Lua 脚本以成员 ID 作为去重集合键，导致成员领取任意权益后无法领取其他权益。已改为以权益 ID 建集合，并在集合内按成员去重，保持“一名成员对同一权益只能领取一次”的既有规则。

## 4. 最终验证证据

- API 场景：38 通过，0 失败。
- 异步订单：接口返回订单 ID 后，已在 `gy_benefit_order` 查询到对应记录。
- 库存一致性：测试限时权益初始库存为 2，异步订单完成后 MySQL 库存为 1。
- 会话一致性：登出成功后，同一令牌访问受保护接口返回 HTTP 401。
- 上传一致性：图片可通过 Nginx 上传并落盘，随后通过删除接口移除。
- 数据隔离：联调使用固定测试手机号和 `GouYu-Integration-` 商户前缀，验证结束后按这些标识精确清理 MySQL 与 Redis 测试数据。

## 5. 运行说明

运行后端前设置以下环境变量，敏感值不要提交到仓库：

```powershell
$env:GOUYU_MYSQL_PASSWORD='<mysql-password>'
$env:GOUYU_REDIS_HOST='<redis-host>'
$env:GOUYU_REDIS_PASSWORD='<redis-password>'
mvn.cmd spring-boot:run
```

项目 Nginx 位于 `deploy/nginx`，启动后通过 `http://127.0.0.1:8080/` 访问前端。
